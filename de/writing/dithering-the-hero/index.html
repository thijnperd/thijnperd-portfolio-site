Der Hero ist gedithert, nicht weichgezeichnet

Die Szene auf der Startseite ist ein normaler Three.js-Render, der anschließend mit einem 8×8-Bayer-Muster auf zwölf Stufen pro Kanal quantisiert wird. Dieser eine Pass macht den größten Teil des Looks aus.

Warum überhaupt dithern

Ein weicher Farbverlauf gehört zu den schwierigsten Dingen auf einem 8-Bit-Display. Geht man langsam genug durch einen Himmel, reihen sich die Rundungsfehler zu sichtbaren Bändern auf. Die übliche Lösung ist Rauschen, das Banding gegen Körnung eintauscht.

Dithering geht diesen Tausch absichtlich ein. Man reduziert die Palette auf eine bewusst kleine Zahl von Stufen und entscheidet dann anhand von Helligkeit und Schwellenmuster, welche Stufe jedes Pixel bekommt. Aus der Ferne mittelt das Auge das Muster wieder zu einem Tonwert; aus der Nähe ist es eine Textur. Diese Textur ist der Sinn der Sache, kein Nebeneffekt.

Der Hero nutzt zwölf Stufen. Wenig genug, damit das Muster sichtbar bleibt, und genug, damit Haut, Holz und Wasser weiterhin als solche erkennbar sind.

Bayer, ganz ohne Nachschlagetabelle

Geordnetes Dithering nutzt eine feste Schwellenmatrix: ein 8×8-Raster aus Werten, das sich über den Bildschirm wiederholt. Üblicherweise speichert man 64 Zahlen in einem Array oder einer Textur. Der Shader baut dasselbe Muster stattdessen rekursiv auf, aus einer einzigen Zwei-mal-zwei-Funktion:

float bayer2(vec2 a) {
  a = floor(a);
  return fract(a.x / 2.0 + a.y * a.y * 0.75);
}
#define bayer4(a) (bayer2(0.5 * (a)) * 0.25 + bayer2(a))
#define bayer8(a) (bayer4(0.5 * (a)) * 0.25 + bayer2(a))

Jeder Schritt halbiert die Koordinate, wertet das kleinere Muster aus und faltet es mit einem Viertel Gewicht wieder ein. Das Ergebnis ist ein Schwellenfeld mit 64 Werten im Bereich 0–1, erzeugt aus wenigen Instruktionen und ohne Speicher. Zieht man 0.5 ab, entsteht der vorzeichenbehaftete Versatz, den der Quantisierer braucht.

Das Muster ist der Grund, warum das Ergebnis wie Druckgrafik wirkt statt wie Fernsehrauschen. Rauschen ändert sich pro Pixel und pro Frame; Bayer wiederholt sich, sodass das Auge Halt findet und das Bild ruhig bleibt, selbst wenn sich die Kamera bewegt.

Ein Pass, nach dem Tonemapping

Die Szene wird normal gerendert, per Tonemapping angepasst und durch einen OutputPass in den Darstellungsfarbraum überführt; erst danach übernimmt der Dither-Pass, sodass die Stufen im Darstellungsraum quantisiert werden statt im linearen Raum, in dem die Szene beleuchtet wurde.

Der Pass tastet nicht jedes Pixel einzeln ab. Er rastet zuerst auf einen Block ein und liest dann die Mitte dieses Blocks:

vec2 block = floor(gl_FragCoord.xy / uPixelSize);
vec2 blockUv = (block * uPixelSize + uPixelSize * 0.5) / uResolution;

vec3 color = texture2D(tDiffuse, blockUv).rgb;

Dieses Detail zählt. Würde jedes Pixel seine eigene Farbe abtasten und dann quantisieren, läge das Muster über dem voll aufgelösten Bild und Kanten würden zu Brei. Indem zuerst die Blockmitte abgetastet wird, teilt sich der gesamte Block eine Eingabefarbe, sodass das Dither-Raster selbst zur Auflösung des Bildes wird. Es ist ein bewusster Verzicht auf räumliches Detail zugunsten einer stabilen, scharfen Textur.

Das Raster ist zwei CSS-Pixel breit

Die Blockgröße wird in Gerätepixeln gesetzt und mit der Device Pixel Ratio skaliert, weil auch gl_FragCoord in Gerätepixeln misst. Ohne diese Skalierung würde derselbe Shader auf einem Retina-Display ein halb so breites Raster erzeugen und das Dithering fast verschwinden.

Das vom Renderer genutzte Pixelverhältnis ist bei 1.5 gedeckelt, und der Block liegt bei 2.0 × dpr (2.2 auf schmalen Bildschirmen). So bleibt das Raster auf dem Smartphone, dem Laptop und dem 4K-Monitor ungefähr zwei CSS-Pixel breit.

Die Palette bewegt sich mit der Szene

Dithering ist nur die halbe Optik. Die andere Hälfte ist, dass die zwölf Stufen keine festen Farben sind: Die Atmosphäre der Szene wird über vier Keyframes abgetastet – Tageslicht bei 0, goldene Abenddämmerung bei 0.46, Zwielicht bei 0.66, Mitternacht bei 1 – und jede Farbe der Szene wird per Smoothstep dazwischen interpoliert.

Derselbe Skalar steuert die Seite. Ein eigenes Paar aus heller und dunkler Palette wird auf der CPU abgetastet und in CSS Custom Properties geschrieben, sodass Papier, Tinte und Akzentfarbe der Abschnitte unterhalb des Hero mit dem Himmel mitwandern. Auch Favicon und Browser-Themefarbe ändern sich mit. Eine Zahl, ein Licht.

Deshalb lässt sich auch der Regler ziehen, statt ein Theme umzuschalten. Es gibt keinen diskreten Dark Mode zum Aktivieren: Es gibt eine Tageszeit, und alles tastet sie ab.

Was es kostet

Der Post-Pass ist günstig; die Szene nicht. Eine komplette Three.js-Szene mit eigener Wellenfläche, Partikeln und Composer ist viel Arbeit für einen Hintergrund. Deshalb wird das Modul erst im Leerlauf geladen statt im ersten Payload, der Renderer pausiert, sobald der Hero aus dem Sichtfeld scrollt oder der Tab verborgen ist, und Besucher mit Save-Data erhalten stattdessen einen statischen Hintergrund. Bei prefers-reduced-motion bleibt die Uhr stehen: kein Driften, kein Einblenden, keine Wellen, aber das Dithering bleibt.

Ein Anti-Flimmer-Detail, das sich zu merken lohnt: Die Papierkörnung nach der Quantisierung wird aus der Blockkoordinate gehasht, nicht aus der Zeit. Rauschen pro Frame auf einem statischen Muster funkelt; Rauschen pro Block wirkt wie Papierstruktur.

Nachlesen

Der Pass liegt in src/hero/dither.js, die Palette in src/hero/atmosphere.js und die Reihenfolge der Passes in src/hero/HeroScene.js. Der Quellcode der Website liegt auf GitHub.
